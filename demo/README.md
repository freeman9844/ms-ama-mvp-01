# 합성 사업자 금융 로컬 데모

사업자의 신청부터 심사, 유동성 경보, 상환 지원, 동의 철회·삭제까지 연결한 시연용 앱입니다. **실제 대출·송금·고객 발송을 하지 않습니다. 실제 개인정보·금융정보를 입력하지 마세요.**

React 화면과 Express 업무 서버, 별도 HTTP mock 원천 서버, 서로 분리된 SQLite DB를 사용합니다. 전체 순서·인가·계산·승인은 코드가 통제합니다.

| 역할 | 구현 |
|---|---|
| Data Assembly | 동의 검사, HTTP 수집, 페이지 완전성·중복·잔액 검증, 코드 전망 |
| Cash-Flow Underwriting | 실제 Copilot SDK의 근거 기반 의견, 최종 승인은 담당자 |
| Early-Warning | 코드 규칙 경보를 먼저 저장하고 실제 SDK가 설명 |
| Collections | 실제 SDK가 지원 경로를 분류, 고정 템플릿을 모의 발송함에 기록 |
| Consent Lifecycle | 즉시 차단, 만료 검사, 계보 기반 삭제, SDK 소유 세션 정리 |

## 준비와 실행

Node.js **24.x**, npm, Copilot 사용 권한과 CLI 인증이 필요합니다. Copilot CLI에서 `/login`으로 로그인한 뒤 모델 목록을 확인하세요. 앱은 현재 대화 세션을 재사용하지 않으며 앱 소유의 별도 SDK 런타임을 만듭니다.

```powershell
Set-Location .\demo
node --version
npm ci
npm run ai:smoke -- --list-models
npm run demo
```

기본 주소는 앱 `http://127.0.0.1:3000`, 원천 `http://127.0.0.1:3001`입니다. 준비 확인 후 두 주소가 출력됩니다. 실행 터미널에서 **Ctrl+C**로 종료하세요. 사용 중인 포트를 점유하거나 다른 서버를 종료하지 않습니다.

다른 포트가 필요하면 실행 전에 설정합니다. `.env.example`은 예시이며 자동으로 읽지 않습니다.

```powershell
$env:DEMO_APP_PORT = "3200"
$env:DEMO_MOCK_PORT = "3201"
npm run demo
```

운영자 계정으로 접속해 **사용 가능한 모델 목록에서 명시적으로 선택·저장**하세요. 미선택·인증 실패·사용 불가 모델을 가짜 응답이나 다른 모델로 대체하지 않습니다. 모델 변경은 새 작업부터 적용됩니다.

## 화면으로 시연하기

1. **사업자 A**: 대출 신청 → 신청 심사 데이터 제공 동의 → 최종 제출. BANK·PG·TAX 동의는 기본 해제 상태이며, 수집 결과를 고객이 별도로 승인하는 단계는 없습니다.
2. **담당자**: 신청의 심사 상세에서 코드 계산, AI 의견, 근거·불확실성을 확인하고 모의 대출을 승인합니다. 조회한 자료·평가 버전과 현재 동의가 일치해야 합니다.
3. **사업자 A**: 데이터 동의 화면에서 별도 사후 모니터링 동의를 등록합니다. 동의가 없으면 모니터링하지 않으며 자동 거절 사유로 삼지 않습니다.
4. **운영자**: 정산 지연을 선택하고 예정일을 `2026-11-05`로 변경합니다. 담당자는 유동성 경보를 확인할 수 있습니다. **예상 부족은 실제 미납이 아닙니다.**
5. **운영자**: 업무 시간을 10일 이동한 뒤, 대상 상환 일정을 선택해 모의 미납 사건을 실행합니다. 날짜 이동만으로 미납이나 출금을 만들지 않습니다.
6. **담당자 / 사업자**: 상환 지원 검토와 모의 안내를 확인합니다. 일반 문의·곤란·정정·고충은 사업자 지원 화면에서도 접수합니다. 날짜 변경은 담당자의 버전 일치 승인만 가능하며 금액 감면·금리 변경은 제공하지 않습니다.
7. **사업자 A**: 데이터 동의에서 철회를 확인합니다. 접근은 즉시 차단되며 삭제 대기·진행·완료 또는 SDK 정리 실패를 따로 표시합니다.
8. **운영자**: 초기화 준비 → 확인. 앱·mock 합성 데이터를 초기화하고 로그인 세션을 폐기합니다. 재로그인하세요.

계정 변경은 로그아웃 버튼을 사용합니다. 고정 데모 계정은 **운영 인증이 아니며** 로컬 사용자는 다른 역할을 선택할 수 있습니다.

## 기준 사례

업무 시계 D0는 `2026-10-28 00:00 KST`입니다. 은행 조회 범위는 `2026-04-28 00:00` 이상 D0 미만입니다.

| 항목 | 일정 | 금액 |
|---|---|---|
| 현재 은행 잔액 | D0 | 300만 원 |
| 미지급 PG 정산 | D+3 | +500만 원 |
| 합성 급여 예정 | D+5 | -600만 원 |
| 가정 / 승인 후 모의 상환 | D+10 | -100만 원 |

정상 7일 최저 잔액은 **200만 원**, 30일 최저·기말 잔액은 **100만 원**입니다. PG를 D+8로 지연하면 D+5~7 예상 잔액은 **-300만 원**입니다. 이후 미확인 현금흐름을 임의로 예측하지 않습니다.

은행 입금과 PG 매출을 더하지 않습니다. 정산 지급 사건은 은행 입금과 PG 지급 상태를 하나의 원천 DB 트랜잭션에서 갱신합니다. 사건 재전송은 중복 입금하지 않습니다. 일중 순서 미확인과 과거 미확인 예정 항목은 불확실성으로 표시합니다.

## 실패와 복구

- 작업 실패는 신청 단계와 별도로 표시합니다. 인증·모델 설정을 고친 뒤 실패 작업의 재시도를 누르세요. 불완전 자료는 정상 심사처럼 공개하지 않습니다.
- 원천 HTTP는 10초 제한, 네트워크·5xx에는 최대 3회 시도합니다. AI의 선택된 일시 오류는 작업당 최대 2회이며 세션 제한은 120초·도구 8회입니다.
- 실행기를 재시작하면 SQLite에 남은 미완료 작업을 임대 만료 후 복구합니다. 기본 임대는 60초이며 완료 작업은 재실행하지 않습니다. 재시작 경계에서 실제 모델 호출 비용이 중복될 수 있습니다.
- 동의는 심사 기본 30일, 모니터링 60일이며 자동 갱신하지 않습니다. 만료 처리기와 무관하게 조회·도구·최종 저장 시 유효성을 검사합니다.
- SDK 정리가 실패하면 삭제를 완료로 표시하지 않습니다. 동의 화면에서 삭제 재시도를 사용할 수 있습니다.
- 초기화 중 실패하면 유지보수 상태로 일반 업무를 차단합니다. 문제를 해결한 뒤 운영자 계정에서 초기화를 다시 확인하세요. 저장된 단계·generation으로 이어서 처리합니다.

## 데이터·보안 경계

데이터는 `demo\.local\demo` 아래 `app.db`, `source.db`, 앱 소유 SDK 디렉터리에 저장되며 Git에서 제외됩니다. 서버는 루프백에만 바인딩합니다. 내부 서비스 토큰은 실행 시 생성하고 자식 프로세스에만 전달합니다.

SDK에는 앱이 제공하는 정책·근거 조회와 한정된 시나리오 계산 도구만 노출합니다. 기본 셸·파일·웹·MCP 도구 및 모든 런타임 권한 요청을 거부합니다. LLM은 승인·DB 변경·메시지 발송을 수행하지 않습니다.

철회·만료 삭제는 해당 동의의 앱 원자료, 전망, AI 평가·경보와 소유 SDK 세션을 대상으로 합니다. 복수 동의 기반 결과도 하나가 무효화되면 전체를 무효화합니다. 독립된 모니터링 자료는 보존합니다. 금융 내용을 복사할 수 있는 사람의 결정 사유는 해당 근거 삭제 시 제거합니다.

별도 근거의 신청·대출·상환·일반 지원·고정 안내·최소 업무 메타데이터는 유지합니다. 기관 역할의 mock 원천 DB는 동의 철회로 삭제하지 않습니다. 갱신은 새 동의이며 과거 삭제 결과를 자동 복원하지 않습니다.

**Copilot 추론은 원격이며 사용량이 발생합니다.** 앱이 원격 보존 정책이나 과금 기록을 삭제할 수 없습니다. 국내 처리 요건·운영 인증·법정 보존·실제 신용위험 성능·공정성을 충족하거나 검증한 제품이 아닙니다. SQLite 행 삭제는 디스크 포렌식 수준의 안전 삭제를 보장하지 않으며, 이 데모는 DB 백업을 만들지 않습니다.

현재 의존성 감사에는 Express / body-parser의 **high 경고 2건**이 남아 있습니다. 공개된 버전 간 권고가 순환하여 자동 업그레이드하지 않았습니다. 앱에서 압축 입력을 차단하고 두 HTTP 파서 모두 `inflate: false`, 32KB 제한을 사용합니다. 이 완화가 `npm audit` 통과를 뜻하지는 않습니다. 외부에 배포하지 마세요.

## 검증

```powershell
npm test
npm run typecheck
npm run lint
npm run format:check
npm run build
npx playwright install chromium --only-shell
npm run test:e2e
```

결정적 브라우저 테스트는 **tests 전용 bootstrap**에서만 모델 대역을 주입합니다. 제품 실행기에는 대역 옵션이 없습니다.

실제 SDK smoke와 세 역할의 제품 실행기·브라우저 여정은 별도 실행합니다. 아래 모델 값은 실제 모델 목록에서 확인한 ID로 지정하세요.

```powershell
$env:DEMO_MODEL_ID = "<사용 가능한 모델 ID>"
npm run ai:smoke -- --model $env:DEMO_MODEL_ID
npm run test:e2e:real
```

실연동 검증은 별도의 임시 DB와 OS 할당 포트를 사용하며, 사용 중인 데모를 초기화하지 않습니다. 모델 미설정은 skip 성공이 아니라 실패입니다. 모델 출력의 특정 문장 대신 구조·업무 상태·근거·로컬 세션 정리를 검사합니다.
